# YO-Trace 真实使用场景与需求验证（任务 0.2 / 0.3 材料）

> 来源：用户在社交媒体搜集到的 3 个真实吐槽场景（2026-08-26 提供）。
> 价值：这三个场景共同证明一个核心痛点——**"明明看过、却找不到"**，且根因不是用户记性差，
> 而是"视觉饱和 / 排序与记忆错位 / 标签页溢出"，即人脑的视觉搜索机制在不同界面下会系统性失效。
> 这正是 YO-Trace 要做的事：用"时间线 + 内容检索"对抗"肉眼在杂乱界面里找东西"。

---

## 场景一：桌面上的"被图标淹没的快捷方式"
- **关键词**：视觉拥挤、图标重叠
- **情景**：装完软件勾选了"创建桌面快捷方式"，回桌面扫了一圈没看到，以为没装上正准备重装，
  结果那个新图标安静躺在左上角，被两个旧图标夹着、颜色和壁纸几乎融为一体，视线直接从它上面"滑"过去了。
- **背后的坑（视觉饱和）**：桌面图标 30+ 时，大脑把所有小方块当成"背景矩阵"，新图标因无显著颜色反差被归为噪音过滤掉。
  网上"桌面越乱越找不到东西"说的就是这个。

## 场景二：文件夹里的"按名称排序找不到"
- **关键词**：排序方式不对、时间线错乱
- **情景**：记得昨天下午 3 点存了"项目方案_v2"，按名称 A→Z 翻遍只有 v1 和 v3，以为忘保存正准备重写；
  点"修改日期"排序后文件赫然在最上面——但它文件名里 v2 前多了个空格（"项目方案 _v2"），按名称排到了"项目"那栏，不在你以为的"V"区。
- **背后的坑（排序与记忆错位）**：你记得的是"时间和内容"，系统默认按"名称字符"排；文件名细微差异（空格/下划线/全角半角）
  彻底改变排序位置。很多人骂"Windows 搜索是废物"，一半原因是排序和命名细节没对上。

## 场景三：浏览器里的"刚才还打开的那个标签页"
- **关键词**：标签页过多、Ctrl+W 误关
- **情景**：浏览器开 20+ 标签页，中间一个是在线文档。随手 Ctrl+W 关了旁边页，过会想切回在线文档，
  在标签栏来回扫几遍没有；翻历史记录几十行也没找到（不记得几点开的）；重新输网址，浏览器提示"此页面已打开"——
  原来它没被关，只是被挤到标签栏最右侧缩成只剩"…"的窄条，你视线一直在中间区域，根本没往右瞄。
- **背后的坑（标签页溢出 + 焦点错位）**：Chrome 约 25 个标签后每个缩到只剩图标/"…"；大脑对标签栏的搜索范围预设在中间，
  不会瞄最右。若恰按了 Ctrl+W，关的是旁边页、目标页被重新激活后位置变了，就误以为"它消失了"。

---

## 共性根因（产品立论）
三个场景看似分散（桌面 / 文件夹 / 浏览器），本质同一：
**用户对"刚才看过什么"有清晰记忆（时间 + 内容），但界面只提供"名称字符排序 / 肉眼扫描"的找回方式，二者错位 → 找不到。**
YO-Trace 的解法不是优化排序，而是**记录屏幕变化、按"时间 + 内容"检索**——让"我大概几点、大概是什么"成为查询入口。

## 对功能规划的映射（输入给后续阶段）
| 场景 | 用户真正想要的查询 | 对应 YO-Trace 能力 |
| --- | --- | --- |
| 场景一 桌面图标淹没 | "昨天下午 3 点我的桌面长什么样？那个新图标在哪？" | 桌面快照 + 时间轴回看 + 截图叠加视图（阶段七） |
| 场景二 排序错位 | "昨天下午改过的、内容跟'项目方案'有关的文件" | 按修改时间 + 标题/内容模糊检索，而非仅文件名（阶段七 FTS5） |
| 场景三 标签消失 | "刚才那个在线文档标签去哪了？我是不是误关了？" | 浏览器/应用活动记录 + 标签页历史 + 检测 Ctrl+W（阶段三 UIA 补充 + 未来增强） |

## 任务 0.3 差异化定位草稿（待用户确认）
- **与 Windrecorder 的核心差异**：Windrecorder 偏"录屏回放 + WebUI 检索"；YO-Trace 偏"把屏幕变化变成**可被搜索的时间线记忆**，
  专门对抗视觉饱和与记忆错位"——主打"按你记得的时间和内容找，而不是和系统默认排序/肉眼扫描较劲"。
- **目标用户**：桌面/浏览器常年拥挤、经常"明明看过却找不到"的普通 Windows 用户（非技术背景也能用）。
- **用户为什么选 YO-Trace**：双击安装、零依赖（阶段八 MSIX）、本地加密不打扰（阶段五）；
  用"时间 + 内容"检索解决上面三类"找不到"，而不是让你在 30 个桌面图标或 25 个标签页里肉眼找。
